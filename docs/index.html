▸ what is this?

Twelve Hawk eval sets with one sample each. Claude Opus 5.5 runs through Claude Code, GPT-6 Sol through Codex and GLM 5.3 Flash through OpenCode, all on OpenRouter at maximum reasoning effort. Scenario A scores time to first token on long prompts, B time per output token, C request throughput under load, and D the geometric mean of all three. Each run has a 16-hour optimisation clock on a RunPod H100, saves a checkpoint every 10 minutes, and restarts from its last checkpoint if the pod fails.

The final speedup restarts the submitted server, measures held-out requests against a naive PyTorch baseline, and applies the MMLU-Pro quality gate and an integrity review. The charts plot the best evaluate.py result each agent has printed so far, divided by the same baseline. Those runs use the agent's development requests and skip the quality gate, so they preview the score; they do not predict it. The dashed line marks the 2-hour budget of the published InferenceBench results.

Status, attempt, agent clock, checkpoints and restores come from Hawk's runner trace. Tokens, cost and speedup history come from attempt logs, which Hawk writes when an attempt ends, so a running attempt shows what its previous attempt recorded. The Hawk viewer can show the previous attempt until a restored run writes its log, so log links may lag while a retry runs.

Spend is the OpenRouter work key's usage since the campaign started (any other use of that key counts too) plus RunPod balance drops. Costs per run use each model's OpenRouter list price at the serving provider.
